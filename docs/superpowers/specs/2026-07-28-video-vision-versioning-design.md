# Davis Video 全量图片理解与版本化重新提交设计

日期：2026-07-28

## 目标

修复两项线上行为：

1. 图片精细优化必须理解当前项目中的全部图片，不设置 3 张上限，不允许自动跳过或降级为文字优化。
2. 已有任务或视频的项目在用户点击“重新编辑”并再次提交时，必须创建独立的新版本项目，命名为“原项目名 V-2”“原项目名 V-3”，旧项目和旧输出保持不变。

## 图片理解流程

- 从当前项目的首尾帧、多帧时间线或纯文字模式参考图片中收集全部去重图片。
- 不再调用代表图截取逻辑，不再限制最多 3 张。
- 采用最多 3 个并发请求，避免大量图片同时调用千问导致限流。
- 每张图片最多尝试 3 次；单次最长等待 45 秒，失败后短暂退避再重试。
- 只有所有图片都返回有效的 `vision_context`，才组装完整上下文并调用 DeepSeek。
- 任意图片在 3 次尝试后仍失败，则终止本次精细优化，显示具体失败图片和原因。
- 不显示“已自动跳过”，不自动降级为文字快速优化，不提供精细模式下的跳过路径。
- 成功状态必须显示 `已理解图片数 / 总图片数`，两者必须相等。

## 版本化重新提交

- 普通首次提交沿用当前流程。
- 用户点击任务或输出上的“重新编辑”时，记录本次编辑属于新版本。
- 用户随后点击生成时：
  1. 保留原本地项目、Supabase 项目、任务、输出和 Google Drive 文件。
  2. 复制当前项目的模式、规格、图片、参考素材、片段顺序、提示词和生成参数。
  3. 清空复制项目中的 `remoteProjectId`、task/provider/segment 绑定、任务状态和输出。
  4. 创建新的本地项目，并由现有首次提交流程创建新的 Supabase `video_projects` 记录。
  5. 将待提交片段映射到复制项目中的同位置片段并提交。
- 新版本名称使用原始基础名称：
  - `冰岛视频` → `冰岛视频 V-2`
  - `冰岛视频 V-2` → `冰岛视频 V-3`
- 版本号同时检查本地项目和当前用户同基础名称的 Supabase 项目，选择最大版本号加一，避免清除浏览器数据后发生重名。
- 新版本创建或提交失败时，只标记新版本失败；旧项目不修改。

## 数据边界

- 不修改数据库结构。
- 不迁移已有视频或图片。
- 不覆盖旧项目的任务和输出。
- 新版本拥有新的 `video_projects.id`。
- 输入素材可以通过现有上传流程重新绑定，新生成输出继续进入 Google Drive。

## 错误处理

- 图片读取失败、千问业务结果无效、请求超时均进入逐图重试。
- 重试耗尽后停止 DeepSeek 调用并保留原提示词。
- 版本号查询失败时使用本地版本集合生成下一个编号，但不会复用旧项目 ID。
- 新项目持久化失败时不执行 Ark 提交。

## 测试与验收

- 1、3、10 张图片全部成功：DeepSeek 仅在全部完成后调用，显示 N/N。
- 10 张图片中一张前两次失败、第三次成功：最终成功且上下文包含 10 张。
- 任意一张连续三次失败：本次优化失败，DeepSeek 不调用，不出现跳过提示。
- 首次提交：不创建额外版本。
- 已完成项目点击重新编辑后提交：创建“原名 V-2”，旧项目与旧视频保持可见。
- 再次从 V-2 重新编辑提交：创建“原名 V-3”。
- 新版本任务写入新的 `video_projects.id`，Drive 输出只属于新项目。
