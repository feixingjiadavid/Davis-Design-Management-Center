# Davis Video A UI Product Cleanup Design

## Goal
恢复 A 方案的项目管理清晰度，同时减少左侧视觉负担：左侧负责“看懂项目和任务”，右上角负责“修改当前任务状态”。

## UX structure

### 左侧项目管理器
- 一级项目保留展开/折叠、项目名、类别、任务数量。
- 一级项目下保留“成片单元”层；历史任务没有成片单元时，不展示“未归类/未分配”等内部词，而统一显示为“待整理任务”。
- 每个任务使用紧凑两行卡片，不出现复选框、状态下拉、状态操作按钮。
- 第一行：任务名 + 当前状态 badge。
- 第二行：生成模式 · 图片/文字数量 · 日期。
- 状态 badge 只展示，不可在左侧编辑。

### 顶部当前任务栏
- 左侧显示归属项目 > 当前任务 > 模式。
- 右侧只显示一个状态编辑器：草稿 / 定版 / 备用 / 需重做 / 废弃。
- 不显示“未分配成片单元”“第1次”等会造成堆叠的内部信息；生成尝试信息后续放到任务详情，不占顶部主导航。
- 只有用户改变状态才更新 review_status；后台同步绝不自动改变 review_status。

### 状态驱动分组
- 左侧按 review_status 自动展示任务状态；右上修改状态后左侧立即同步。
- pending_review 在界面统一映射为“草稿”，但不主动写回数据库，避免后台状态迁移。

### 新建项目交互
- 创建弹窗只允许“取消”或创建成功关闭。
- 点击遮罩、拖动到弹窗外、Esc 都不关闭。
- 类别默认值为正式类别列表第一项，不默认“其他”。

## Visual rules
- 左侧不再使用大面积状态分组卡、粗重边框和重复背景。
- 任务高度目标 56–68px，一屏至少可浏览 8–12 个任务。
- 状态 badge 小而稳定，不与日期、数量或模式抢行。
- 顶部状态编辑器独立成组，保证在 1280–1920px 宽度下不发生文字重叠。

## Safety
- 不修改 Seedance 提交流程、Ark 费用确认、任务输出、历史视频数据。
- 不自动重试，不自动付费生成。
- 不改变现有数据库结构。
