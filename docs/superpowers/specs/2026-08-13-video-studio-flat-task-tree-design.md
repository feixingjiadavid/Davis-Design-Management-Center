# Davis Video Studio 左侧任务树简化设计（R18）

## 目标

把默认信息架构从「项目 → 成片单元 → 生成任务」简化为「项目 → 生成任务」。第一次使用的用户不需要理解“成片单元”或“未归类”才能完成视频生成。

## 核心原则

1. 一级“生成项目”仍是业务项目容器。
2. 项目下默认直接展示生成任务卡片；用户可直接新建任务、上传素材、编辑并生成。
3. “成片单元”保留为高级、可选的业务分组，只在用户主动创建后出现。
4. “未归类”不再作为用户可见分组。没有成片单元归属的任务直接显示在项目下。
5. 已有成片单元和历史任务数据不删除、不迁移、不改写，只改变展示与操作入口。
6. 不修改 Seedance 生成核心、付费确认、账号 owner 隔离、任务状态持久化规则。

## 默认左侧结构

```text
生成项目
└─ test                               ＋任务
   ├─ 1   首尾帧   [备用]
   └─ 2   多帧     [备用]
```

项目行承担主要入口：展开/收起、选择项目、新建生成任务。

## 可选分组结构

只有用户主动创建分组后才显示成片单元：

```text
周年活动
├─ 互动暖场视频                     ＋任务
│  ├─ 张三｜5周年   [定版]
│  └─ 李四｜5周年   [备用]
├─ 开场视频                         ＋任务
│  └─ 开场动画      [定版]
├─ 采访包装                         ＋任务
│  └─ 包装片段A     [备用]
└─ 其他直接任务
   └─ 临时测试       [废弃]
```

“其他直接任务”只是一种视觉排布说明，不在 UI 中显示这个标题；直接任务仍直接排在项目层。

## 入口设计

- 项目行右侧保留 `＋`，含义明确为“新建生成任务”。
- 项目展开区域顶部可保留一个轻量 `＋分组` 入口，替代当前高权重的 `＋成片单元`。
- 分组头右侧保留 `＋任务`，用于在该分组下创建任务。
- 不再在创建一级项目后强迫用户先创建成片单元。创建一级项目后直接进入“新建生成任务”流程。

## 数据与归属

- `video_project_groups` 仍表示一级项目。
- `video_projects` / 本地 draft 仍表示生成任务。
- `video_deliverables` 仍表示可选成片单元。
- 任务 `deliverable_id` 为空时，直接显示在项目层；不包进“未归类”。
- 任务 `deliverable_id` 有值时，显示在对应成片单元下。
- 现有 `video_deliverables` 数据保留，不自动删除或重新归类。

## 渲染策略

R54 不再先把所有项目子任务清空后统一包成“成片单元/未归类”结构，而应：

1. 读取基础 R50 项目任务列表。
2. 对每个项目，将有 `deliverable_id` 的任务移动到对应可选分组。
3. 没有 `deliverable_id` 的任务保持项目直属卡片。
4. 没有任何成片单元时，项目树视觉上保持标准两层结构。
5. 仅在项目存在成片单元时插入对应分组节点。

这避免把后台数据模型强制暴露为用户必须理解的层级。

## 创建流程

### 新建项目

`新建视频项目 → 创建一级项目 → 自动打开新建生成任务`

不再自动触发“新建成片单元”。

### 新建直属任务

`项目 ＋任务 → 选择模式 → 创建生成任务`

任务 `deliverable_id = null`。

### 新建分组任务

`＋分组 → 创建成片单元 → 分组 ＋任务 → 创建生成任务`

任务保存对应 `deliverable_id`。

创建分组后不再自动强迫用户马上创建任务；分组和任务是两个独立动作，减少“套壳”感。

## 状态与选中

现有任务卡片和状态规则保持：

- 定版：绿色
- 备用：黄色
- 废弃：红色
- 未明确标记：业务 UI 按备用处理

任务选择、右上状态同步逻辑不得因 R18 层级调整而改变。

## 权限

继续保持账号严格隔离：

- 每个账号只读取自己的项目、任务、分组和输出。
- 每个账号都可以在自己的项目中创建直属任务、创建分组、上传素材和生成。
- 不引入跨账号共享。

## 错误与空状态

- 项目无任务：显示“还没有生成任务”，并给出 `＋ 新建生成任务`。
- 分组无任务：分组内显示轻量“还没有任务”，保留 `＋任务`。
- 不再出现“未归类”标题。
- 不因任务没有 `deliverable_id` 提示错误；这是正常的直属任务。

## 回归测试

必须新增/更新自动化检查，至少锁死：

1. `buildUnclassifiedNode` 不再用于默认树渲染，UI 不出现“未归类”。
2. 没有成片单元时，项目下任务直接显示，不新增第三层容器。
3. `＋分组` 为低权重可选入口，`＋任务` 仍是主操作。
4. 创建一级项目后直接打开新建生成任务，不创建默认成片单元。
5. 已有 `deliverable_id` 的任务仍能显示在对应成片单元下。
6. 任务状态、右上三状态同步、账号隔离现有回归继续全部通过。
7. 不修改 `app-v46.js`、`ffmpeg-class-worker.js` 和付费生成保护。

## 验收标准

第一次使用者打开新项目后，不需要理解“成片单元”即可在项目下直接看到和创建生成任务。

默认视觉应只有：

**项目 → 任务卡片**

只有主动使用高级分组后，才出现：

**项目 → 可选分组 → 任务卡片**
