# Davis Video Studio 左侧任务树最终简化设计（R18）

## 目标

左侧任务树对用户只展示两层：**项目 → 生成任务**。

用户创建 A 项目后，A 项目下面直接就是 1、2、3、4、5…这些生成任务。用户界面不再出现“成片单元”“未归类”或任何 A1/A2 子分类。

## 最终规则

1. 一级项目是唯一用户可见目录层。
2. 所有生成任务，无论后台 `deliverable_id` 是否为空，都直接平铺在所属项目下。
3. `video_deliverables` 继续保留为后台历史/兼容数据，不删除、不迁移、不参与左侧树层级。
4. 左侧不显示“成片单元”“＋成片单元”“＋分组”“未归类”“视频1”等分组节点。
5. 项目下唯一主要操作是 `＋任务` / `＋ 新建生成任务`。
6. 创建项目后直接创建第一个生成任务；创建第二、第三个任务时继续直接加入同一项目，不再自动分组。
7. 任务卡片的模式、图片数量、日期、状态标签保持现有视觉规范。
8. 定版/备用/废弃和右上状态同步逻辑保持不变。
9. 账号 owner 隔离保持不变。
10. 不修改 `app-v46.js`、`ffmpeg-class-worker.js`、Seedance 付费提交和人工确认保护。

## 渲染策略

基础 R50 已经能够按 `parentGroupId` 将所有 draft 直接渲染在项目下。R18 不再让 R54 清空 `project-child-list` 后重组成 deliverable/unclassified 容器。

R54 的左侧职责缩减为：

1. 找到基础 R50 已渲染的 `.project-child` 任务卡片。
2. 为每张任务卡片添加/同步一个状态 pill。
3. 不移动任务 DOM，不重新排序，不 `replaceChildren()`，不创建额外目录节点。
4. 当 R50 因新建任务或切换项目重新渲染列表后，R54 只做幂等装饰。

这同时消除创建后 R54 二次重组项目树造成的明显闪烁。

## 创建流程

### 新建项目

`新建视频项目 → 创建项目 → 自动打开新建生成任务 → 创建第一个任务`

### 新增任务

`项目右侧 ＋ / 项目下 ＋新建生成任务 → 创建任务`

新任务直接进入该项目下，与第一个任务同级。

### 历史 deliverable 数据

历史任务即使带 `deliverable_id`，左侧也直接平铺到项目下。后台字段继续保留，避免破坏历史审计或其他后端依赖。

## 闪烁要求

- 创建任务后不得出现“任务先出现 → 被 R54 移走 → 再出现”的多次闪烁。
- 点击任务不得因为 R54 层级包装而重排左侧 DOM。
- R54 MutationObserver 如保留，只允许执行幂等状态装饰，不允许重建任务树。

## 回归测试

必须锁死：

1. `enhanceTree()` 不调用 `replaceChildren()`。
2. 默认树不创建 `buildUnclassifiedNode()`。
3. 默认树不创建 `buildDeliverableNode()`。
4. UI 不显示“未归类”“＋ 成片单元”“＋分组”。
5. 带 `deliverable_id` 的历史任务仍作为直属任务卡片显示。
6. 新建项目后仍直接打开生成任务创建流程。
7. 新建第二个任务仍落在同一项目下。
8. 状态 pill、右上状态同步、owner 隔离现有测试全部继续通过。
9. 不修改付费生成核心文件。

## 验收标准

用户创建 `test` 项目后，左侧只看到：

**test → 1 / 2 / 3 / ...**

不会看到任何额外目录、成片单元或未归类。创建新任务后左侧只增加一张任务卡片，不出现明显二次闪烁或层级跳动。
